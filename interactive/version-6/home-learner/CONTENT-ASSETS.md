# Content and asset plan

## Current deliverables

The current Android V2 generated set contains a physical Android-device hero and three portrait screens: setup, capture and review/correction. All use Head cam as the lesson source. Files and dimensions are listed in [manifest.json](manifest.json); each prompt is retained in prompts/. These are flattened raster studies. No editable app layout, streaming feed, trained weights or real participant recordings are included.

The earlier Model Workshop art (earlier study; not included in this selection) remains preserved. Use it only when discussing the earlier simple object-classification route. Current presentations should lead with the home demonstration hero and camera-source choices.

## Lesson content to author later

Pack my bag needs a short teaching script, a successful demonstration, near misses and deliberately incomplete examples. Include notebook visible but not packed; bottle placed beside the bag; charger partly hidden; an empty bag; another notebook; altered lighting and a different table. Reviewers need an annotation guide distinguishing object presence, contact, placement and verified completion. The initial classifier may support only the first of these.

Voice labels should be short and varied. Store the recorded phrase separately from any transcript and approved semantic label. A sentence such as “I forgot the charger” must not become a positive charger-packed example merely because the noun appears. Silent lessons remain fully usable.

## Asset records

Each captured segment needs a session and source identifier, timestamps, orientation, original file reference, retention choice and processing location. An annotation adds its label, interval or frame, reviewer, status and revision. A dataset manifest lists approved examples and split assignments. A model manifest identifies its capability, preprocessing, training dataset, weights/version and evaluation record.

Raw media, thumbnails, extracted features and transcripts are separate artifacts with explicit lineage. Deleting or replacing one should reveal which derived artifacts remain. Export should describe what is included rather than offering an opaque “all data” promise.

## Human capture choices

The owner chooses a room or region and checks whether other people are present. Sensitive areas can be excluded by camera placement, manual cropping, pause or segment deletion. A moving head camera makes fixed masks unreliable; do not present a mask as a guarantee. Proposed automatic redaction remains optional future work with visible review.

Before any optional cloud step, show the chosen clips or features, destination and purpose. Home media should not be uploaded simply because a source is connected. Future device workers receive only the material needed for an explicitly accepted job. The concept should remain valuable with local capture and manual annotation alone.


Android V2 art uses a centered punch-hole device cue, Android status/gesture treatment and warm chalk/charcoal/citron. Production assets would still need editable type, tonal roles, icons, layout constraints and accessible touch regions. A generic photographed Android shell does not claim compatibility with a particular manufacturer or head-camera device.
