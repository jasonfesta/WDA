## Visual review questions

Can a viewer identify each rabbit from silhouette alone? Does the equipped weapon match the same character's turnaround and menu image? Can the environment be recognized as the requested bright stylized suburb rather than a resort? Is the central aiming area visibly clear? Do raider, hopper and foreman read as different enemy roles at gameplay scale?

Inspect the map and hero scene together. An appealing isolated street image is not enough if the encounter map suggests an incompatible place. The map remains a concept layout; reviewers should judge route logic and landmarks rather than demand precise navigable coordinates from it.

## Future implementation gates

These are requirements for a later authorized build, **not completed tests**:

1. A new player reaches the first encounter using only the visible tutorial cues.
2. Selection, equipped model, weapon effect and ability description stay consistent for all three fighters.
3. Health, ammo, cooldown and result values match actual simulation state.
4. Enemies telegraph attacks and cannot spawn unseen directly on the player.
5. The first level can be completed and retried without reloading the application.
6. Pause and focus loss stop a solo run; resume does not create an accidental shot.
7. Menus support keyboard focus, remapping and readable contrast.
8. Reduced motion settings visibly reduce camera shake and flashing effects.
9. Performance is measured on declared desktop and any claimed mobile targets.

## Scope check

Do not mark multiplayer, a battle-royale storm, a construction system, monetization, a mobile release or a complete 3D asset pipeline as accepted. Those are absent from the current deliverable. The next decision is whether this specific first-level concept and corrected visual world merit a separate production phase.
