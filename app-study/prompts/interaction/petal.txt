WDA / Petal — interaction and motion implementation prompt

Read data/flows.json for this app, interaction/petal.md, and interaction/motion/petal.md before implementation. Implement the full documented flow including auxiliary routes and recovery; five images are representative states, not a linear five-step slideshow.

ART DIRECTION
Original Petal art direction: precise painterly lemon, blossom and leaf botanical artwork on creamy paper; expressive refined serif headlines, muted olive utility text, warm coral controls, thin botanical dividers. Preserve the original illustration-based strip puzzle, not abstract colour bars.
Fonts: Cormorant Garamond, DM Sans. Palette: #FFF9EC, #718064, #E8795B, #993D2A. Preserve full-bleed square edges, airy internal spacing, exact UI content and no OS chrome.

APP MOTION
Animate the actual botanical strips and their alignment. The pleasure comes from a small, precise snap and the whole picture coming together, with the calm illustration carrying the atmosphere.
Build BotanicalPuzzle with one source illustration and five clipped horizontal bands. Store normalized x offsets per puzzle ID, selected strip and completed IDs. During horizontal drag use direct pointer movement and capture only after intent; keep vertical scroll available. Snap when within 4% of board width of the valid alignment, using 180 ms ease-out; invalid release returns to its last valid offset in 180 ms. Tap a strip then its alignment target, or keyboard arrows with Enter to place and Escape to cancel, performs the same move. No inertia, confetti, random progress or video-driven game state. Completion checks all five offsets and saves one ID; reduced motion places immediately.

INTERACTION RULES
Touch is primary. Enable rollover only for (hover: hover) and (pointer: fine). Every hover cue has a focus-visible equivalent; no action or information is available only on hover. Pointer exit restores the resting style without changing selection. Use native buttons, links and labeled fields, not clickable artwork.

Proposed tokens: hover 120 ms; press tint 80 ms; focus outline immediate; route crossfade 160 ms; small state changes 180 ms; expanded content 220 ms. Ease with cubic-bezier(0.2, 0, 0, 1), without overshoot. No animation delays navigation, saving or focus.

Play at most one 4-second decorative introduction on first eligible entry per session, then settle to the approved still. Do not replay on field focus, typing, tab return or scroll. This is the default without adding new controls to the approved screens. Continuous motion is a later option only with a visible, keyboard-operable Pause animation control; record that as an additional control before implementation.

effectiveReducedMotion = system preference OR saved app preference. When true, use a static poster, freeze shader time and 3D poses, remove parallax, and apply state changes immediately. Functional pointer-following remains direct, with no inertial or settling animation. Text and status feedback remain complete.

Use normal document scroll; never hijack scrolling or move the foreground type with a background effect. Decorative layers stay inside their illustration region. Suspend them when offscreen, document-hidden, an editor has keyboard focus, or a modal covers the screen. Return to the same phase without catch-up bursts.

Keep text, navigation and forms in the DOM above pointer-events:none, aria-hidden decorative layers. A missing asset, failed video, unavailable WebGL or context loss immediately shows the approved still. Media is muted, plays inline and does not request sound or device-motion permissions. Measure a target of 30 fps for ambient rendering; cap DPR at 1.5 initially and fall back when consistently slow. These are design budgets, not measured results.

VERIFIED BUILD REFERENCES
- Motion · Gesture animation: https://motion.dev/docs/react-gestures
  Application: Hover, press, focus and drag APIs support feedback on real controls. Specific timings and visual treatments in this study are WDA proposals.
- W3C · Dragging movements: https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html
  Application: Dragging needs a single-pointer alternative. Petal retains tap-select and tap-target controls as well as keyboard input.
- Motion · Accessibility: https://motion.dev/docs/react-accessibility
  Application: Reduced-motion policy can govern transforms and custom media behavior. The app must also stop its own shaders and decorative video.
- MDN · Page Visibility API: https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API
  Application: Document visibility changes let the application suspend decorative media when the page is hidden. Resume from state rather than counting background frames.
